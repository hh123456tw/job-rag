# 28: 白盒化介面（分數、可點引用、耗時與 token）

**Blocked by:** 21、22（已完成）
**Status:** ready-for-agent

來源：使用者提供的「RAG 面試官想看什麼」清單第 2 點。目標：讓面試官在畫面上直接看到系統怎麼想，不是黑盒子。**不接外部追蹤工具**，用我們自己的輕量版。

- 每一段原文顯示「相似度分數」（bge-m3 最高相似度的同一個數字）與門檻標記（例如「0.734 ≥ 0.700」；低於門檻的段落淡色並標「低於門檻」）。分數取自檢索結果，不重算。
- 答案中的引用編號 `[1]` 變成可點：點了展開「看原文」並捲動、短暫標示第 n 段。出處標籤同樣可點。沒有 JS 時維持原樣（不壞）。文字一律 textContent，不得有 XSS。
- 每次請求顯示真實耗時與用量：檢索耗時（伺服器端量測）、整理答案耗時，以及 DeepSeek 回應裡的 token 用量（輸入／輸出）。沒有就不顯示（例如替身答案），**不得填假數字**。顯示成步驟列的一部分或答案卡下方一行小字，簡約。
- API 只做加法：`/api/search` 帶每段的 `score` 與 `threshold`、`search_ms`；`/api/answer` 帶 `answer_ms` 與 `usage`（有的話）。既有欄位與行為不變；展示／自用模式、存取碼、用量上限、查無規則不變。
- 展示與自用模式都適用；自用模式的橘色橫幅不變。
- [ ] 測試：分數與檢索結果一致、門檻標記正確（高於／低於／剛好等於）、耗時為非負數、usage 缺時不顯示、引用編號轉成可點且對應正確段落、超出範圍的編號（例如 [9]）不變成壞連結、惡意文字被跳脫
- [ ] 瀏覽器實測（375×812 與 390×844，淺色與深色）：分數標籤、點 `[1]` 後展開並標示、耗時列；量 scrollWidth；回報貼出看到的
- [ ] 既有測試全過
