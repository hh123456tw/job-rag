# 32: 專案說明頁改成「現場講解」順序

**Blocked by:** 無
**Status:** ready-for-agent

來源：使用者說 /about 一打開不知道怎麼講，想要像現場展示給面試官的說明，可以分段、有順序（他不太會講）。

## 做法（只改 /about 的呈現，不動 RAG 邏輯與數字來源）
1. 頂端一行「講解順序」：1 → 2 → 3 → 4 → 5，可點跳到各段；每段標題前有步驟編號與「約 30 秒」。
2. 每段固定三塊：**① 一句話主張**（大字）、**② 給面試官看的證據**（現有的表格／數字，數字照舊取自輸出檔）、**③「你可以這樣說」**（兩到三句口語稿，白話、短句、不用術語；放在折疊的「講稿」或淡色區塊，面試官畫面上不搶眼，但使用者看得到）。
3. 建議順序（沿用現有 6 塊內容重排，不新增事實）：①這是什麼與為什麼做 → ②資料與切段（只放公開事實） → ③怎麼找（5 種找法、為何選 bge-m3，附 MRR 白話） → ④怎麼確認答對（RAGAS、GPT 複查、查無門檻） → ⑤我踩到的坑與三次修正（票 30） → ⑥限制與下一步（含放大 100 倍，用白話圖書館比喻）。若現有內容不適合這個順序，說明原因再調整。
4. 加一個「簡報模式」鍵：按下去一次只顯示一段，大字、上一步／下一步、手機單手可按，結尾有「問答備案」（常被追問的 5 題：資料放大、為什麼不用 reranker、為什麼混合沒贏、門檻偏樂觀、沒向量資料庫但仍是向量檢索）。簡報模式要在 375 寬可用。
5. 講稿文字誠實：不誇大；「沒做」的就說沒做；不得出現「AI 協作」類說明；數字以輸出檔為準，檔缺就略過該句。

## 不要做
- 不新增頁面路由以外的後端功能；不改檢索、門檻、答案。
- 不用外部函式庫；純 HTML/CSS/少量 JS。

## 驗收
- [ ] /about 有講解順序與編號；每段有主張、證據、講稿三塊
- [ ] 簡報模式 375 寬可用，上一步／下一步、鍵盤左右鍵可用
- [ ] 既有 /about 測試全過（必要時更新斷言，但數字來源測試不得放寬）
- [ ] 公開匯出掃描通過（注意：`about_page.py` 不得出現被禁的字，見票 29 的做法）
- [ ] 全套 pytest 結束碼 0（直接取 pytest 的結束碼，不要接管線）
