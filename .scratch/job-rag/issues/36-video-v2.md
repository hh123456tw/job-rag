# 36: 備援影片第 2 版（配音更自然、畫面有節奏、改用台灣大哥大示範）

**Blocked by:** 票 34（已合併）
**Status:** ready-for-agent

使用者回饋（第 1 版）：配音很糟（機器感重）；畫面單調，像在看長長的螢幕錄影，要有「短影音」的節奏與效果；示範公司改用**台灣大哥大**。

## 要做的
1. **配音**：重新評估免費且自然的中文（台灣口音）配音。先讀 `media-use` skill 列出的選項，再比較至少 2 種（例如 Microsoft Edge 神經語音 `zh-TW-HsiaoChenNeural`／`HsiaoYuNeural`／`YunJheNeural`（用 `edge-tts` 套件，免帳號、免費；腳本文字會送到微軟服務，內容是公開的示範稿，OK）、HyperFrames 內建 Kokoro 等）。每種各合成同一句 10 秒試聽 wav 放 `demo/backup_video/voice_samples/`，**回報比較與你的選擇**；選最自然者。**不付費、不申請帳號、不下載大型模型**（pip 小套件可以，先說明）；若最好的選項需要帳號或付費，停下回報，改用次佳的免費選項。語速自然、句間有停頓、重音合理；數字、「RAG」「DeepSeek」這類詞要念對（必要時用同音字或 SSML）。
2. **示範公司改台灣大哥大**：流程仍是：首頁 → 點公司（台灣大哥大）→ 問「薪水多少？」→ 點 [1] 看原文與分數 → 回首頁問跨公司「哪些公司用 Python？」→ 專案說明簡報模式翻兩頁。**真 DeepSeek 呼叫約 6–8 次，答案必須是真實出現的，不得剪成假結果**；錄完後逐句核對口語稿只說畫面上真的有的內容（例如薪資區間要和畫面答案一致，不要寫畫面沒有的數字）。
3. **畫面與節奏（HyperFrames）**：先讀 `hyperframes-animation`、`hyperframes-creative`、`hyperframes-registry`、`hyperframes-keyframes` skill，優先用 registry 現成的區塊（轉場、字幕、重點標示）。目標 55–70 秒，竪式 1080×1920：
   - 片頭 3 秒：標題大字動畫（「求職情報問答」＋一句話主張），保留「示範錄影，電腦螢幕錄製，非真機」。
   - 每 4–7 秒換一個鏡頭／景別：整頁 → 拉近答案區（punch-in／Ken Burns，用 keyframes，不是剪假畫面）→ 重點圈出（高亮框、箭頭、放大標籤：分數標籤「0.735 ≥ 0.620」、[1] 引用、「查無就說查無」）。
   - 手機框＋乾淨背景（品牌色 `#2563eb` 系，深色底），UI 錄影放在手機框內；轉場要克制但明顯（滑動／縮放，不要過度閃爍）。
   - 動態字幕（逐句、關鍵字上色），與配音逐句同步；音量均衡；若加背景音樂，只能用 `media-use` 提供的可商用／免費來源，音量低於配音 -18 dB 以上，並在說明檔註明來源與授權；沒有合適來源就不加。
   - 片尾 4 秒：三行誠實聲明（資料來源公開、非真機、評估題少只能當方向）。
4. 口語稿全文放 `demo/備援影片說明.md`（更新），標哪些畫面是真實錄到的。
5. 影片存 `demo/backup_video/demo_backup_v2.mp4`（保留 v1 不刪）。< 50MB。

## 不要做
- 不啟動 ngrok、不停止或重啟 5000 埠服務、不讀 `.env`／`selfdata/`；影片只用展示模式、不得出現存取碼或本人密碼；不宣稱真機錄製；不剪假結果；不誇大（不說準確率 100%）；不 push。
- 專案路徑含中文會讓 HyperFrames 的 Chrome 當掉：在英文路徑副本渲染（說明檔已記載）。
