# 22: 對話記憶（帶入最近 2 輪）

**Blocked by:** 21
**Status:** ready-for-agent

**使用者決定：** 選「C：把最近 2 輪問答交給 DeepSeek」，讓追問（例如「那薪水呢？」）可以用。

**What to build:** 在公司對話框（以及「全部公司」對話框）中，讓追問能被理解。

設計要點（都要做）：
1. **伺服器不存對話。** 由前端把該對話框最近 2 輪（問題＋助理答案文字）隨請求送出；伺服器驗證：最多 2 輪、每則答案截斷到 300 字、總長上限、型別檢查，超過就截斷或拒絕（回明確 JSON 錯誤），不得信任內容。
2. **檢索要跟著補全**（只靠提示詞補全不夠，因為短問句檢索會因為分數低被查無門檻擋住）：當前問句很短或沒有公司／主題詞（規則簡單且可解釋，例如 12 字以內且不含公司名與任何主題關鍵字）時，把上一題的使用者問句接在前面做檢索。規則寫在一處、有測試、README 一句話說明。不使用 LLM 改寫問句（避免多一次呼叫與延遲）。
3. **整理答案的提示詞加入「先前對話」區塊**（最近 2 輪）：明確指示「事實只能來自下方段落；先前對話只用來理解『那』『它』指什麼，不得把先前的回答當成證據」。答案仍須附出處；沒有可引用內容回「查無」。
4. 查無門檻、私人段落不進索引、存取碼、用量上限（每次答案請求計一次）、低分不呼叫 DeepSeek 的規則都不變。
5. **迷你評估（追問題）：** 建立 8 到 10 組「前一題＋追問」的題目，金標用檔名＋標題路徑、引文用程式核對真的出現在金標之下（沿用評估題的做法；狀態寫「待使用者確認」）。分別量「不補全」與「補全」兩種做法的 Hit@3，如實報告（題少，只當方向；補全沒有變好也要如實寫）。
6. `/about` 加一小段（白話）：「對話會記住最近 2 輪；追問補全是簡單規則；追問只用 N 題量過」。N 與數字由輸出檔讀取。限制要寫：只量了檢索，沒有量多輪答案品質。
7. 專案說明與 README 不得出現「AI 協作」類說明、私人內容。
