# 21: 答案優先、兩步到答案的手機介面

**Blocked by:** 票 15、19、20（已完成）
**Status:** ready-for-agent

**使用者回饋（手機實測）：** 作為使用者我覺得很難用：不知道從哪開始、只看到一大段原文、版面或操作不順。

**What to build:** 把介面改成「選公司 → 點問題 → 看到答案」兩次點擊內完成，答案優先，原文收在下面。

- 首頁只做一件事：大標題與一行說明（「選一家公司，再點問題」），11 顆公司大按鈕；另有一個「或直接輸入問題」的輸入框（跨公司）。
- 選了公司後：頂端顯示公司名與清楚的「← 換一家」；下面是 4 顆大的問題按鈕（做什麼、有哪些職缺、用什麼技術、財務與新聞）加輸入框。點問題立即送出，不需再按其他鈕。
- 結果頁：最上方是「答案」卡（DeepSeek 整理，附出處標籤）；原文 3 段收在「看原文」`<details>` 之下。原文先出現（立刻），答案在背景載入，顯示「整理中…」，載入後填入；失敗、逾時、無網路、用量上限時，顯示明確訊息並自動展開原文，不出現假答案。沒有 JS 時退回現有「整理成答案」按鈕。
- 低分（可能沒有答案）時：不呼叫 DeepSeek，顯示提示，原文淡色並展開（維持現有規則）。
- 結果頁要保留所選公司，頂端有「← 換問題」與「← 換一家」。
- 排版：手機內文至少 17px，點擊區至少 48px，間距寬鬆，單欄，沒有橫向捲動；淺色與深色都可讀；維持簡約、PWA 與存取碼、用量上限。
- 專案說明頁 `/about` 的事實陳述要同步（原本寫「預設只顯示原文、按鈕才用 LLM」，要改成「答案優先，失敗時回到原文」），且測試要涵蓋；不得出現「AI 協作」類說明。
