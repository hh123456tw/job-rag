# 24: 自用／展示切換

**Blocked by:** 23
**Status:** resolved

依 SPEC「修正五」。使用者需求：「我需要有一個切換自用和展示用的按鈕」。

- [ ] 自用資料：環境變數（例如 `JOB_RAG_SELF_DIR`，預設 `selfdata/`）指到本機資料夾；內含私人段落（研究筆記被排除的標題段落、作戰卡）與面經檔。沒有此資料夾或沒設密碼，就沒有自用模式，行為與現在完全相同
- [ ] 兩個索引分離：展示索引永遠只有公開事實段落；自用索引 ＝ 公開＋私人。向量快取放 `.cache/`（已被 git 擋住）。`search()` 的模式參數預設展示
- [ ] 切換鈕：頁首「展示｜自用」；切到自用要輸入本人密碼（`JOB_RAG_OWNER_PIN`，不同於存取碼）；伺服器端簽名 cookie（HttpOnly、SameSite=Lax、https 時 Secure、效期短）；錯誤嘗試次數上限（例如 10 分鐘 5 次）並使用常數時間比對；切回展示立即生效並清掉自用對話（sessionStorage 與畫面）
- [ ] 自用模式的 API（`/api/search`、`/api/answer`、頁面）沒有有效的本人 cookie 一律當展示處理，**不是報錯後洩漏**；用測試鎖定
- [ ] 自用模式的畫面有橘色橫幅：「自用模式：資料會送到 DeepSeek，請勿給別人看」；對話串、公司頁、提示卡都標明目前模式
- [ ] 自用模式下私人段落可送 DeepSeek；展示模式下送出內容仍只含公開事實段落（用混合語料的測試證明）
- [ ] 不同模式的對話記錄、記憶（票 22）互相隔離
- [ ] 專案說明頁與公開匯出不含任何私人資料；匯出白名單與掃描更新：`selfdata/`、含 `OWNER_PIN` 值的檔案一律不得出現
- [ ] 用瀏覽器實際走：展示→輸入錯誤密碼→輸入正確密碼→橘色橫幅→查一題私人資料→切回展示→確認查不到；375×812 截圖
- [ ] 通道（ngrok）情境：持有存取碼的人預設展示；沒有本人密碼無法進自用
