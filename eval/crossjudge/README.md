# 跨模型複查（非 RAGAS）

- 目的：RAGAS 的評審與生成同為 DeepSeek，可能自我偏好。另請 GPT（經 Codex CLI，預設模型，`codex exec -s read-only`）用同一份答案與段落獨立複查。
- 做法：把答案拆成事實陳述，逐項判斷段落是否支持；規則見 judge_prompt.md；每批 8 題；輸出 JSON 陣列。輸入只含公開事實段落。
- 輸入來源：`eval/results_generation.json`（RAGAS 已評分的 22 題，contexts＝當時送給模型的段落）與 `eval/results_heldout_generation.json`＋`results_heldout_answers_v2.json`（獨立題 24 題，答案相同、段落取自 v2 的 contexts）。被查無門檻擋住或回「查無」的題不送。
- 檔案：
  - `input_new.json` → `judge_gpt_new.json`（同內容複製成 `judge_gpt.json`，說明頁讀這個檔）：題組 22 題。
  - `input_heldout.json` → `judge_gpt_heldout.json`：獨立題 24 題。
  - `judge_gpt_old_2026-11-16.json`、`input.json`：舊版（舊語料）。
- 結果（2026-11-17，新版語料、K=5；GPT 單次輸出有隨機性，重跑可能略有不同）：
  - 題組：22 題、295 個陳述中 295 個有支持、0 個不支持；忠實度平均 1.0。
  - 獨立題：24 題、148 個陳述中 148 個有支持、0 個不支持；忠實度平均 1.0。
  - 不支持的陳述是 0 個，所以沒有需要人工判斷「GPT 錯或答案錯」的項目。
- 人工抽檢（2026-11-17）：
  - supported 隨機抽 10 個（種子 20261117，跨 h25、s13、s06、j02、s14、j10、j12），回原段落核對，10 個都在對的公司段落裡找得到依據。
  - 另外程式檢查：443 個陳述的 evidence 有 442 個逐字出現在該題段落（1 個 h01 是兩段引文用分號接起來）；陳述點名公司的，evidence 都在該公司標題的段落內（只有 j07 的「聯合線上」對應標題為「聯合報」，是別名，不是錯）。
  - 針對 RAGAS 有扣分的 s06（0.941）、s10（0.867）、h22（0.545）、h23（0.929）逐題讀了 GPT 的拆法：GPT 全判有依據。差異主因是拆陳述的方式不同，例如 h22 答案有 5 行「資料沒寫」，GPT 規則不當事實陳述，RAGAS 可能當成陳述。RAGAS 沒存逐陳述判定，無法逐一對照；這是推測，沒有驗證。
  - 風險：GPT 的 evidence 常是短詞（如「CSS」「重試」），代表它只確認「段落有這個詞」；抽檢的 10 個都再讀過上下文，語意也符合。
- 舊版結果（2026-11-16，舊語料）：22 題、268 個陳述中 268 個有支持、0 個不支持；忠實度平均 1.0。
- 限制：兩個評審都只量「答案有沒有依據」，不量答案對不對；題少；GPT 評審沒有用 RAGAS 流程，是同規則的獨立複查；兩個評審結論一致偏樂觀（接近滿分），分辨力有限。
