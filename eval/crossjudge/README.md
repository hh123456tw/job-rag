# 跨模型複查（非 RAGAS）

- 目的：RAGAS 的評審與生成同為 DeepSeek，可能自我偏好。另請 GPT（經 Codex CLI，預設模型，`codex exec -s read-only`）用同一份答案與段落獨立複查。
- 做法：把答案拆成事實陳述，逐項判斷段落是否支持；規則見 judge_prompt.md；每批 8 題；輸出 JSON 陣列。輸入只含公開事實段落。
- 重跑：`python -X utf8 eval/crossjudge/run_judge.py build|judge|report`（build 由 RAGAS 輸出組輸入檔，judge 呼叫 GPT，report 印統計）。每批失敗最多重試 2 次；這次沒有失敗批次、沒有重試（`judge_failed.json`）。
- 輸入來源：`eval/results_generation.json`（30 題組，RAGAS 已評分的 22 題）與 `eval/results_heldout_generation.json`＋`results_heldout_answers_v2.json`（獨立測試題 100 題中 RAGAS 已評分的 69 題，答案相同、段落取自 v2 的 contexts）。被查無門檻擋住或回「查無」的題不送。
- 檔案：
  - `input_new.json` → `judge_gpt_new.json`（同內容複製成 `judge_gpt.json`，說明頁讀這個檔）：30 題組 22 題。
  - `input_heldout.json` → `judge_gpt_heldout.json`：獨立測試題 69 題。
  - `judge_gpt_old_2026-11-16.json`、`input.json`：最早一版（舊語料）。`judge_gpt_old_2026-11-17_before_titles.json`：補職稱清單之前的語料（22 題、295 個陳述全有支持）。
  - 舊 40 題獨立題的複查在 `eval/old_heldout40/`，不再引用。
- 結果（2026-11-18，補完職稱清單的語料、K=5；GPT 單次輸出有隨機性，重跑可能略有不同）：
  - 30 題組：22 題、293 個陳述中 293 個有支持、0 個不支持。
  - 獨立測試題：69 題、304 個陳述中 299 個有支持、**5 個不支持**（g019 1 個、g074 1 個、g092 3 個）：
    - g019「資料中沒有提到其他職位的地點」：段落其實有列其他職缺的地點。
    - g074「華電聯網在新竹的技術職缺總共有兩個」：段落只列兩個，但職稱清單被截斷，無法確認「總共」。
    - g092「叡揚資訊的雲端條件只提到公有雲基本操作」：段落還有雲端產品設定，不只這一項。
    - g092「聯合報資料科學資深經理職缺屬於資料發展部」：段落標題寫「數據發展部」，答案寫錯名稱。
    - g092「聯合報從 2018 年起把線上服務與資料分析搬到 Google Cloud」：段落只說 2018 年決定搬上雲端並選 Google Cloud，沒說當年起實際搬遷。
  - 這 5 個我讀過答案與段落：g092 的「資料發展部」（名稱寫錯）與「2018 年起搬到」（說過頭）核對段落後確認屬實；其餘 3 個（「只提到」「總共兩個」「沒有提到其他職位」）是過度概括或否定句，GPT 判得合理但較嚴。g019 與 RAGAS 對同題的低分一致。沒有請第二人確認。
- 讀法：GPT 這次不是全數放行，代表它有分辨力；但兩個評審都只量「答案有沒有依據」，不量答案對不對。30 題組兩次（新舊語料）都接近滿分，只能當方向。
- 限制：題少；GPT 評審沒有用 RAGAS 流程，是同規則的獨立複查；GPT 的 evidence 常是短詞，代表它只確認「段落有這個詞」；金標與題目由單一模型出，沒有人工確認。
- 另有實際連線測試的複查：live_judge_gpt.json、live2_judge_gpt.json、live3_judge_gpt.json（見 eval/live_test.md，舊語料）。
