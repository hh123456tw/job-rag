# 備援說明（個人用，不公開）

## 答案為替身示意，非真實 DeepSeek 回應

`screens/` 的截圖用本機測試伺服器拍的：`JOB_RAG_FAKE_ANSWER=ok`（開發用替身）、假的 `DEEPSEEK_API_KEY`、沒有設存取碼、沒有設自用密碼（展示模式）。
- 答案框的文字是替身產生的一句模擬文字，開頭寫「（開發用替身的模擬答案）」，**不是真實 DeepSeek 回應**。每張截圖頂端也有紅條註明。
- 檢索結果（步驟列的段落標題、看原文的原文）是真的：用真的語料與 bge-m3，只有答案那一句是假的。
- 03 的處理中畫面：測試時把答案請求暫停約 1.5 秒再放行，才拍得到「整理答案」那一行與跳動的點。
- 截圖用 Playwright 驅動系統 Chrome，視窗 375x812、2 倍解析度，行動裝置模式；沒有用 Browser pane 工具，因為它不能把截圖存成檔案。

## 缺的畫面與原因

- **真實 DeepSeek 的答案畫面**（04 與 05 的真實版）：這次不呼叫真的 DeepSeek（花錢、需金鑰），由你另外補。建議存成 `04-答案完成-真實.png`。
- **DeepSeek 失敗畫面**（紅字原因＋自動展開原文）：沒拍。要拍可設 `JOB_RAG_FAKE_ANSWER=fail`。
- **後續題目送出後的畫面**（腳本第 44–50 秒）：沒拍。
- **手機真機畫面**：沒有。截圖是桌機 Chrome 的行動裝置模擬，不是真手機。
- **展示模式與自用模式的切換畫面**：不拍，也不用在演示。
- **公開網址（ngrok）與手機熱點的實際連線畫面**：沒測，沒有啟動 ngrok。

## 沒有螢幕錄影

我這邊無法錄影。請用手機內建螢幕錄影，自己錄一段 60 秒流程（照 `演示腳本.md`，用真的 DeepSeek），存在手機相簿。錄影時不要拍到網址列裡的存取碼。

## 什麼時候用

現場網路或熱點失敗、筆電連不上、手機打不開網址時：

1. 先播手機錄影；沒有錄影就翻 `screens/`，依 01 → 08 順序。
2. 直說「現場網路出問題，這是事先錄的／截的畫面」。若翻的是這裡的截圖，再說「答案那一句是測試替身，不是真實回應」，不要假裝是即時操作。
3. 用 `面試追問準備.md` 的數字口述專案說明頁。
